One agent or five?

For these three tickets, one agent would have been better. It would use fewer tokens and skip the back and forth between agents. In our run every agent re-read the ticket and the cash balance for itself, and each handoff repeated the facts. Boss alone used 16–22k tokens per ticket. One agent would likely land around 20–30k per ticket instead of 47–58k (an estimate; we didn't run it), and it couldn't call Accounting twice. More agents can also slow things down: the double Accounting calls on 102 and 103 happened because two agents asked for the same work.

What we'd lose with one agent:

  • On 102, Facilities checked the rent notice before Accounting prepared the $2,400 payment. With one agent, nobody checks the work.
  • Only Accounting can request money, and Customer Service can't. One agent would have every tool.
  • The audit trail shows which agent did each step, so we could see the 103 price came from Boss.

The 103 pricing mistake would have happened with one agent too, because it came from the prompt's discount rule. We still like having more agents on the team. For a bigger shop with more tickets, we'd keep the specialists but have them work one at a time.

What we'd improve

  1. A discount policy: up to 10% for student groups, 10–20% only with a human's OK, and never quote at the 15% margin floor. Add a request_discount_approval tool so discounts go to the same human queue as payments.
  2. One call per specialist per ticket: if Accounting is already working on a ticket, ask_teammate waits for its report instead of starting a second run. That saves about 12.7k tokens.
  3. Customer drafts say "proposed" unless an approval exists, and never show the percent off or our margin.
  4. Update statuses after approvals: when every request on a ticket is paid, Boss sets 102 to resolved and 101 to waiting_on_stock.
  5. Approval order on the board: grey out the $8 PO until invoice 501 is approved.
